## Resource, format and plural checks

All twelve bundles have the same 91 non-UI `AppStrings` fields and 120 `UiStrings` fields: **252 leaf strings per language**, 3,024 total. No null/empty leaf values or missing live-focus getters were found. Every locale has 12 month names, 7 weekday labels, 6 shift rules and 7 hour-help items. The four current hour labels contain exactly the intended visible factor tokens 1.0×, 1.5×, +0.5× and 2.0×.

Both live formatted messages (`ui.selectedTemplateBannerFormat`, `ui.deleteTemplateMessage`) preserve one `%s` argument in every locale. All 24 were also passed through Java `String.format` with a synthetic title containing a literal percent and quote, without errors. Percentage prose elsewhere is not treated as a format template.

The Android XML resource contains the application name; localization is primarily Kotlin data objects, not parallel `values-xx/strings.xml` trees. No Android `<plurals>` resource exists in this surface. Numeric work-hour/day displays concatenate localized unit abbreviations or count-invariant unit nouns, which do not by themselves require English-style plural selection. Russian `ч`/`дн`, English `h`/`d` and Korean counters avoid a missing quantity-form branch. Native date grammar is a separate issue (C04/C05).

A Russian-default equality scan found only KY `ui.versionLabel` as a candidate in non-Russian UI bundles. `Версия` can be a Kyrgyz IT loanword, so this is not recorded as confirmed untranslated text. Deliberate Korean payroll terms, English `OT`/`holiday` in Filipino, symbols and coefficient notation are likewise not automatically classified as missing translations.

Numeric display helpers currently use `Locale.US` and therefore decimal dots for physical-hour values. That is a presentation consistency risk for comma-decimal locales, not a changed coefficient or an arithmetic defect; this audit does not alter number parsing/formatting.
